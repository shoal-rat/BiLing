# 对弈 · 知音 vs Apple 拼音（第一轮：子期 r2）

**结论：在 1119 条逐条配对的留出语料上，知音 70.4%，Apple 拼音 64.6%，差 +5.8 个百分点，95% 置信区间 [+3.1, +8.5]，不含零。**
领先主要来自带前文的输入、整句、缩写与新闻文本；Apple 在无前文的聊天短句和手误输入上仍然领先。

## 环境

machine: Apple M5, 16 GB, macOS 27.0.1 (26A434)
- Apple 拼音：`com.apple.inputmethod.SCIM.ITABC`，由 `Tools/duel/duel.swift` 以真实按键驱动（前文写进文本框、光标在末尾；空格上屏其第一候选）。Apple 的用户学习状态无法重置，是这台机器长期使用后的状态。
- 知音：`tiaoyin eval`（与输入法同一个解码器），子期 r2（听音 LoRA，r2 第 6166 步）+ 知意（原始 Qwen3-0.6B-Base Q4_K_M），束宽 10，琴谱补漏开启，空默契。
- 运行过程中测试工具有一段失去焦点，Apple 有 142 条输出为空（连续的第 420–440、462–582 条）；这 142 条已单独重测并替换，重测后无空输出。

## 语料

`Tools/duel/build_duel_set.py --seed 20261002`：1123 条（配对后 1119 条，4 条因前文、键、答案三元组重复而合并），全部来自训练从未见过的来源：

| 来源 | 条数 | 说明 |
|---|---|---|
| 聊天 | 500 | LCCC **测试**切分（训练只用了训练切分） |
| 新闻 | 500 | Leipzig 新闻 2020（训练只用了 2007–2009） |
| 当代用语 | 123 | 手写留出句（`Tests/Corpus/modern-heldout.txt`），与训练的新词包不重复；作者即系统作者，存在选择偏差，单独报告 |

跨度：短语（2–6 个音节）606 条、整句 513 条；打法：全拼 802、轻缩写 100、重缩写 86、手误 131；带前文 713、无前文 406。
按键由 pypinyin 加一个独立写成的打字模型生成，**不**用知音自己的模拟器或读键规则；知音拼不出来的条目照样计分。
所有解码参数只在另外 600 条调参集（`duel-dev.tsv`，句子与测试集不重叠）上选择。

## 读法

- **前文是知音的立身之本**：带前文 +8.6（CI 不含零），无前文基本持平（+1.0）。
- **新闻 +16.0，整句 +10.1，缩写 +11 / +18.6**：两只耳朵在长输入和缩写上明显更强。
- **聊天无前文 −5.5、手误 −5.3**：口语短句和拼错是下一轮的重点——r3 训练加入了手误样本与新词包。
- 速度：这一轮的配置（束宽 10、补漏）每个按键 p50 约 260 ms（M5，Metal），比 Apple 慢得多；见 `ARCHITECTURE.md` 的能耗一节与后续轮次。
