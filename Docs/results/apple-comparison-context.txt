Paired with-context comparison vs Apple Pinyin (2026-07-29)
===========================================================
Machine: Apple M5, 16 GB, macOS 26 (build recorded by `sw_vers` at run time);
Apple IME = com.apple.inputmethod.SCIM.ITABC via CGEvent harness
(scripts/apple_baseline.swift --context: the item's committed context is
seeded into the text view with the caret at the end — the same
surrounding-text channel any app gives an IME — and only text appearing
after the seed is read as the answer). BiLing = full system (Qwen +
dual-mode gate), scripts documented in docs/apple-comparison-protocol.md.
Caveat inherited from the protocol doc: Apple's own user learning cannot be
reset and its state on this machine is part of the system under test.

Numbers below are after re-sweeping the model blend weight for the
bridge's corrected score semantics (the merged-tokenization fix scores the
whole candidate; the old path skipped its first token — the ceiling moved
0.55 -> 1.0 cold / 1.2 with context, ScoreModel.languageModelScale; the
split exists because above 1.0 cold the model's style bias outvotes corpus
frequency, caught by the release gate).

1) General text: 150 items sampled from the held-out derived test set
   (first 150 rows with non-empty context and a-z-typeable keys).
     BiLing 77.3%   Apple 77.3%
     paired difference +0.0 pts, 95% CI [-6.0, +6.7]; wins/losses/ties
     12/12/126 (paired bootstrap, B=10000, seed=20260729)
   -> statistical parity, identical point estimates. For reference, the
      frozen no-context comparison (260 items, apple-comparison.txt) had
      Apple ahead by 10.4 points. Committed context closes the gap.

2) Context disambiguation: Tests/Corpus/contrast.tsv (43 authored items
   where the same pinyin must resolve differently by context).
     with context:  BiLing 83.7%   Apple 67.4%
       paired difference +16.3 pts, 95% CI [+2.3, +30.2]; w/l/t 9/2/32
       -> the CI excludes zero: the lead is supported at the 95% level.
     no context:    BiLing 41.9%   Apple 46.5%
   -> The honest summary: Apple still leads cold; with context the systems
      tie on general text and BiLing leads significantly exactly where the
      design aims — resolving by committed context. "SOTA" is not claimed;
      one machine, one Apple learning state, n=43 on the focused corpus.

Commands:
  .build/release/biling-cli --evaluate <tsv> [--no-context] --per-item out.tsv
  swift scripts/apple_baseline.swift <tsv> <n> [--context] > out.tsv
  python3 scripts/paired_bootstrap.py biling.tsv apple.tsv
